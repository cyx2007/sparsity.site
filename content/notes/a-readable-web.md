打开一篇文章时，最直接的期待通常很简单：看见标题，读懂内容，顺利地读到最后。

但一个网页的制作过程，常常从其他地方开始。选一套组件，搭一个导航，设计几张卡片。等框架已经显得十分完整，文字才被放进去，去适应那些提前准备好的位置。

如果把顺序调过来，会发生什么？

## 先放一段真的文字

真正的内容，会比占位符更早暴露设计问题。

一个标题可能有十八个汉字，一段正文可能夹着英文术语，一行代码可能很长。它们在宽屏上表现良好，换到手机上却不一定如此。

所以，与其先画出一个理想的容器，不如先选几段具有差异的内容：一个短标题、一个长标题、一段连续的文字、一条引用。让它们成为设计开始时就存在的约束。

## 一行有多长

阅读的节奏，来自许多小尺度的决定。字的大小、行与行之间的距离、一个段落的长度，以及眼睛从行尾返回下一行开头时需要跨越的距离。

这些参数没有适用于所有字体的固定答案。可以先把正文限制在舒适的范围，再带着真实的内容反复调整。

```css
.prose {
  max-width: 38rem;
  font-size: 1.125rem;
  line-height: 2;
  overflow-wrap: anywhere;
}
```

这几行样式并不是完整的解决方案。它只是一个起点：让布局首先对文字负责。

## 不打断也是一种照顾

一篇文章读到中间，弹出的提示会迫使读者暂时离开刚才的思路。即使关闭只需要一次点击，那条思路也未必能立刻接上。

对一个以阅读为主的网站而言，克制有非常具体的意义：不遮住正文，不让内容突然位移，不把必要的导航藏在猜测之中。

链接应该看起来像链接。标题应该能帮助定位。关闭脚本后，文字依然应该留在页面上。

这些事情没有那么显眼，但它们共同决定了一个页面是否让人愿意继续读。

## 纸以外的可能

把网页理解为一张纸，并不是要舍弃网页的能力。

网页可以在不同大小的屏幕上重新排版，可以让目录直接指向某个段落，也可以让引用连接到原始出处。它比纸多出来的能力，应该帮助理解内容。

设计的起点可以很朴素：先让一行文字被舒服地读完。然后，再看看还需要什么。
